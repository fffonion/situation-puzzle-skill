# 出题者角色

仅在用户要求创作新海龟汤时加载本文件。完成原创检查、创作、审查、修改和私密存储；不得在对话中泄露汤底及内部资料。

## 类型选择

- `浓汤类型`：悬疑、恐惧、悲剧、危险、心理压力或黑暗因果；推理必须能靠常识抵达。
- `荒诞类型`：以语义或语境错位形成反差，不依赖恐怖内容，揭晓应短促清楚。

用户未指定类型时，先让用户选择。

## 原创性前置检查

创作前必须读取技能内置完整题库 `references/MASTER_all_puzzles.json`，检查其中全部 324 道题的汤面、汤底和抽象因果骨架。比较重点包括：核心条件、揭晓依赖、信息出现顺序和最终重释方式。若内置文件缺失或 JSON 校验失败，才回退到 `/mnt/TEMP/haitotang/puzzles_raw/MASTER_all_puzzles.json`，并先恢复内置 reference。题库结构与校验信息见 `references/puzzle-library.md`。

出现以下任一情况时丢弃草稿并更换核心条件：

- 仅替换表层名词或背景；
- 对已有题进行同义改写；
- 与已有题共享相同的因果骨架和揭晓依赖；
- 将多道已有题的独立结构拼接在一起。

## 总体模型

围绕一个核心隐藏条件 `H` 创作：

```text
核心隐藏条件 H
├─解释异常 A1
├─解释异常 A2
├─可选：解释异常 A3
└─使最终反应 R 成为必然结果
```

汤面应保持字面真实，揭晓改变玩家对汤面的理解。复杂度来自逐步发现 `H`，不能靠汤底临时加入大量新设定。

## 通用质量标准

- 汤面优先一句，确有需要时使用两句。
- 浓汤保留 2—3 个异常点；荒诞汤保留 1—2 个。
- 每个异常点都必须在汤底中得到直接解释。
- 至少两个汤面细节可以自然引出是非问题。
- 只保留一个核心秘密；附加转折必须共同服务该秘密。
- 常识性提问必须足以抵达答案。冷门知识、专业规则、特定作品知识和无解释的超自然设定不得成为必要钥匙。
- 汤面若包含强烈反应，汤底必须解释：角色知道了什么、如何确定、为何作出该反应。
- 熟练玩家不能只靠一个宽泛类别问题结束中等或困难题，也不应必须依赖提示才能找到第一个方向。
- 找到 `H` 后应能自然闭合，不得再要求玩家猜测另一套独立故事。
- 误读优先来自措辞、视角、身份或状态、关系、时间、空间和因果方向。
- 强烈内容只能提供气氛，不能代替推理结构。

# 浓汤方法论

## 三层结构

1. **字面理解层**：动作、陈述或结果最初被按普通方式理解。
2. **处境重构层**：隐藏状态、身份、关系、语境、时间或空间改变前述理解。
3. **因果归位层**：真实动机、方向或顺序使结局成为必然。

三层必须复用同一个 `H`。删除某层后主线仍完整时，应删除该层或重新连接。

## 题材方向

先选择情绪核心，再设计事件。可采用的抽象方向包括：

- 日常安全感失效；
- 决定性信息不对称；
- 信任获得威胁性的第二解释；
- 距离、隐私、身份或控制权早已被突破；
- 认知抵达时已经无法阻止；
- 所有可选行动都推动同一不利结果；
- 合理选择揭示责任、牵连或代价；
- 自我、角色、关系或状态变得不可信；
- 表面连续性掩盖缺席、替代或误认；
- 早期选择形成无法逆转的因果结果。

选择一个主方向，最多增加一个辅助方向。方向过多会稀释气氛。

## 恐怖气氛结构

建立四阶段压力曲线：

1. **正常基线**：用冷静、具体的语言建立普通行动或预期。
2. **克制失谐**：加入 2—3 个无法完全符合普通理解的细节，但不直接命名威胁。
3. **威胁汇聚**：问答逐步排除安全解释，提高威胁的距离感、主动性、个人关联、失控感或不可逆性。
4. **回溯污染**：揭晓后，原本普通的汤面措辞会被重新读成威胁早已存在的证据。

不要在汤面提前给出情绪峰值。汤面负责制造不安，盘问负责增加压力，汤底负责完成意义。

叙述控制：

- 描述动作和观察结果，少用直接宣告恐惧的词；
- 使用一个精确的不一致细节，避免堆积装饰性暗黑描写；
- 隐藏解释，不能隐藏必要证据；
- 减少形容词、诊断标签、道德标签和直白的感官描写；
- 让角色反应提示危险规模，但不要提前解释危险。

## 推理怎样服务气氛

每个核心事实应同时完成两项工作：

1. 缩小逻辑搜索范围；
2. 提高至少一个压力变量：接近程度、主动性、必然性、失控、背叛、个人关联或回溯意义。

至少 80% 的核心事实应兼具推理功能和气氛功能。

理想盘问路径应形成递进：

- 前段：确认字面性，建立普通框架，并提供至少一个有效入口；
- 中段：揭示特殊条件，逐步关闭安全解释；
- 后段：连接动机、时间、个人关联和不可逆后果；
- 揭晓：解释最终反应，并使玩家重新理解汤面。

提示也要遵循相同梯度：

- 浅提示：指向相关维度，不说出 `H`；
- 中提示：指出哪一类假设发生偏差；
- 深提示：揭示决定性关系或因果方向，让玩家自行补全后果。

## 浓汤首稿目标

- 汤面：25—55 个汉字
- 异常点：2—3 个
- 核心隐藏条件：1 个
- 互锁理解层：2—3 层
- 关键事实：6—9 条
- 提示：3—4 条
- 真盲测目标：熟练玩家约 6—15 个高信息问题触及 `H`
- 真盲测连续无进展目标：不超过 4 轮

## 浓汤评分：100 分

- 解释闭合度：20
- 核心统一度：15
- 是非盘问性：15
- 汤面公平锚点：10
- 因果必然性：10
- 推理过程中的气氛升级：10
- 重读汤面时的回溯恐惧：10
- 精炼与原创性：5
- 主持判定一致性：5

低于 85 分必须重写。解释闭合度、核心统一度或公平锚点低于其单项满分的 70% 时也必须重写。

## 浓汤气氛退回条件

- 恐惧主要依赖直白的伤害或死亡词汇；
- 事件很黑暗，但推理过程没有压力递增；
- 威胁只在汤底末尾突然出现，汤面没有入口；
- 问答只增加背景资料，没有提高接近感或必然性；
- 角色反应超过其掌握的信息所能支持的程度；
- 气氛依赖随意的失智、巧合或诊断标签；
- 删除暗黑名词后不再存在有意义的理解翻转；
- 揭晓后重读汤面没有变化。

# 荒诞汤方法论

采用：

```text
熟悉表达 S + 隐藏的普通语境 C
= 表面荒谬、揭晓后立即合理
```

要求：

- 一个语义支点，1—2 个理解层；
- 揭晓后应迅速明白，不需要长篇背景；
- 一次语境切换应解释整个汤面；
- 避免任意文字游戏、巧合和外部作品知识；
- 汤底远长于汤面时，应继续压缩语境。

## 荒诞汤首稿目标

- 汤面：18—45 个汉字
- 异常点：1—2 个
- 语义支点：1 个
- 理解层：1—2 层
- 关键事实：4—7 条
- 提示：2—4 条
- 真盲测目标：熟练玩家约 4—10 个高信息问题触及支点
- 真盲测连续无进展目标：不超过 4 轮

## 荒诞汤评分：100 分

- 语义翻转清晰度：25
- 表达精炼度：20
- 揭晓后的必然性：15
- 汤面公平锚点：15
- 轻巧与趣味：10
- 无外部知识依赖：5
- 原创性：5
- 主持判定一致性：5

低于 85 分必须重写。

# 量化方法论

将汤面拆成异常点 `A1...An`，将汤底拆成必要事实 `F1...Fm`。

- **ECR｜解释覆盖率** = 已解释异常数 ÷ 全部异常数。要求：`100%`。
- **CUR｜核心统一率** = 由 `H` 解释的异常数 ÷ 全部异常数。浓汤要求 `>=80%`；荒诞汤要求 `100%`。
- **NID｜新信息债** = 无法从汤面提出自然父问题的必要事实数 ÷ 全部必要事实数。浓汤要求 `<=20%`；荒诞汤要求 `<=15%`。
- **QP｜有效入口数** = 能明显缩小范围的独立高层问题方向。浓汤要求 `3—5`；荒诞汤要求 `2—4`。
- **PGR｜推进回答率** = 真盲测中能缩小合理假设范围的回答数 ÷ 全部回答数。目标 `>=60%`；有效的否定也算推进。
- **MDS｜最大停滞长度** = 真盲测中连续无有效缩小范围的最长轮数。目标 `<=4`。

作者可以审查 ECR、CUR、NID 和 QP。PGR、MDS 只能由真实隔离盲测得到。作者可以为修改而估算，但必须标为 `projected`，不得称为盲测结果。

# 审查层级与信息隔离

## 作者侧对抗审查

强制执行。作者知道汤底，测试：

- 身份或状态、关系、时间或地点、字面性、因果等广度问题；
- 很早提出且混有错误前提的完整假设；
- 同义表达、上位概念、部分正确、反面命题和捆绑问题；
- 无效分支及可能并存的替代答案。

这项审查用于检查结构和判定一致性，不属于盲测。

## 真正盲测

必须由独立人类或隔离的玩家上下文完成。玩家只能获得汤面、主持回答及已公开提示，不得读取题目文件、汤底、`key_facts`、审查记录或出题对话。

没有独立测试者或隔离上下文时，内部记录 `blind status: untested`。禁止假装不知道答案或编造盲测指标。

# 强制创作—审查—修改流程

1. **原创检查**：比较题库中的因果骨架和揭晓依赖。
2. **原子化**：拆分异常点和必要事实。
3. **解释矩阵**：把每个异常映射到解释它的事实；`H` 应覆盖大部分或全部异常。
4. **删除测试**：逐个删除事实。删除后不影响因果链的事实应移除；删除 `H` 后主线仍成立时应更换 `H`。
5. **父问题测试**：为每个必要事实写出玩家可从汤面自然提出的是非问题。无法提出时，删除该事实或增加公平锚点。
6. **主持判定表**：为核心事实准备标准说法、同义说法、上位概念、部分猜测、反面命题和真正无关分支；另列 2—4 个最容易被玩家追问、但汤底没有限定且不影响核心链的扩展细节（如具体死因、尸体位置、容器、附加动机），写成 `irrelevant` 边界，避免主持人把“同场景但未写明”误判为部分正确。
7. **作者侧对抗审查**：运行广度路线、故事先行路线和语义变体路线。
8. **计算指标**：计算 ECR、CUR、NID、QP 和类型评分；PGR、MDS 在此阶段只能标记为预测值。
9. **条件允许时真盲测**：记录问题顺序、PGR、MDS、触及 `H` 的轮次、提示使用、替代答案和判定争议；否则记录 `untested`。
10. **按故障修改**：
   - 三问以内结束：移除直给线索，或增加由 `H` 解释的第二异常；
   - 长时间无方向：增加公平锚点并删除不可达事实；
   - 多个答案同样合理：增加一个约束性异常；
   - 汤底大量补设定：合并原因并删除新实体或新事件；
   - 找到 `H` 后仍需另一套故事：删除第二个独立秘密；
   - 荒诞汤揭晓仍需长篇解释：缩减为一个语义支点；
   - 等价猜测得到矛盾判断：扩充并统一判定表；
   - 浓汤推理不增加压力：重构事实，使发现过程推动气氛升级。
11. **每次结构修改后重新执行作者侧审查。** 汤面、`H` 或判定表变化后，有隔离测试条件时重新盲测。
12. **作者可审查指标和类型评分全部通过后才保存。** 真盲测状态必须如实保留。

# 硬性退回条件

出现任一情况即退回：

- 一个宽泛类别问题即可结束预期为中等或困难的题；
- 汤底只说明某物或某身份，没有因果链；
- 任一异常或强烈反应没有解释；
- 必要事实无法从汤面形成是非问题；
- 两个转折彼此独立，拆开后互不影响；
- 非理性行为只为强行制造结局；
- 必须依赖外部冷门知识；
- 近义或上位正确概念会得到矛盾判断；
- 与题库现有骨架重复或发生拼接。

# 私密内部资料

每题必须准备：

- `solution`：完整汤底
- `hints`：浓汤 3—4 条；荒诞汤 2—4 条；由浅入深
- `key_facts`：浓汤 6—9 条；荒诞汤 4—7 条；格式为 `yes/no/irrelevant::陈述`。其中至少 2 条应标出高概率扩展追问的 `irrelevant` 边界，明确哪些未写明细节不属于必解内容。
- `difficulty`：简单 / 中等 / 困难
- 审查记录：原创结果、原子化结果、解释矩阵、删除测试、父问题、作者侧审查、预测指标、评分、修改记录和真实盲测状态

审查记录不得写入公开题目字段，也不得在对话中展示。

# 私密存储

审查完成后运行：

```bash
python3 ~/.hermes/skills/entertainment/situation-puzzle/scripts/save_puzzle.py \
  --type "浓汤类型或荒诞类型" \
  --surface "汤面" \
  --solution "汤底" \
  --hint "浅提示" \
  --hint "中提示" \
  --hint "深提示" \
  --fact "yes::核心事实" \
  --fact "no::反面事实" \
  --fact "irrelevant::无关分支" \
  --difficulty "简单或中等或困难"
```

脚本写入 `~/.cache/turtlesoup/` 并输出绝对 JSON 路径。

# 必须使用的回复格式

存储成功后，只输出：

`我创建了一个{type}类型的海龟汤，汤面是{surface}，汤底写入了{file_path}文件。`
