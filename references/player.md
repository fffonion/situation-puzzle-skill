# 玩家角色

仅在助手需要猜题、协作猜题或进行真盲测时加载本文件。玩家不得读取私密题目文件、汤底、`key_facts`、出题审查记录或出题对话。

## 模式

- `单人玩家`：每轮提出一个信息量最高的问题。
- `协作玩家`：提出 1—3 个候选问题，并给出一个简短的当前假设。
- `盲测`：把题目当作黑箱，只记录公开汤面、已发布提示和主持回答。

默认规则：

- 对话中已经出现汤面或主持回答时，默认使用 `单人玩家`。
- 用户要求一起猜时，使用 `协作玩家`。

## 信息隔离

真正盲测的玩家只能获得：

- 公开汤面；
- 主持人的 `是`、`不是`、`是也不是`、`不相关` 判断；
- 主持明确发布的提示。

不得请求、定位、查看或根据文件名推断私密 JSON。若当前上下文已经见过汤底或出题审查记录，该上下文已受到信息污染，不能给出真盲测结论；应说明盲测无效，并要求使用隔离的玩家上下文。

## 材料归纳：有效轨迹的结构

题库中的 324 条整理后问答轨迹明显偏向保留有效路径：肯定或接近肯定约占 88%，第一次肯定回答通常出现在第 1—2 个保留问题，连续肯定链的中位长度为 3，绝大多数轨迹以最终确认结束。原始节目记录包含更多误判、重复和无效分支，因此这些数据表示“编辑后的有效逻辑链”，不能当作真实玩家每局只需少量问题。

有效路径的共同点是：玩家没有把肯定回答当作奖励或孤立线索，而是把它变成下一层问题的父节点。肯定回答之后约九成仍连接另一个肯定节点，说明高效推理依赖连续收窄和跨异常连接。

## 核心原则：`是` 表示一条边，不表示整片故事

每次得到 `是`，只确认问题中被主持判定的精确命题。不能自动继承相邻假设，也不能把自己的完整脑补一并视为成立。

内部维护五类记录：

1. **已确认事实**：主持明确判定为真；
2. **仅确认相关**：某维度重要，但具体内容尚未确定；
3. **有限肯定**：`是也不是`、`接近`、`部分成立`、`可以这样理解`等，表示问题中至少有一条主线部分成立，同时另有错误、未限定或视角不同的部分；必须拆分命题；
4. **已排除事实**：主持明确否定；
5. **未决假设**：尚未询问或问题含义不够单一。

禁止把“相关”写成“为真”，禁止把有限肯定升级为完整肯定。

## 肯定回答的六种功能

### 1. 入口肯定

确认某个高层维度值得继续，例如身份或状态、关系、时间、空间、字面性、意图、后果或因果。下一问应在该维度内做互斥切分，不能立刻跳到完整故事。

### 2. 类别肯定

确认一个上位类别。下一问应把该类别分成少量互斥子类，优先选择能最大幅度缩小范围的划分，避免逐项枚举具体对象。

### 3. 关系肯定

确认两个节点存在联系，但尚未确认方向、强度、时间和因果。下一问只补一条边：谁影响谁、联系发生在何时、是否直接、是否出于主动意图。

### 4. 机制肯定

确认某个动作、状态或转换方式。下一问应询问该机制解释了哪个汤面异常，或它是否导致最终反应；避免继续堆积无关细节。

### 5. 有限肯定

问题中通常同时包含正确部分和错误表述。把原问题拆成最小命题，每轮只验证一个部分。保持已经确认的抽象层级，只改变一个变量，不要整套重猜。

### 6. 闭合肯定

完整假设获得确认后，不再扩写背景。检查每个异常是否已被解释、最终反应是否成立、是否还有未确认的必要事实；全部覆盖即可结束。

## 得到 `是` 后的固定处理流程

```text
得到肯定
→ 写下被精确确认的最小命题
→ 判断它属于节点、属性还是边
→ 选择一种后续操作
   ├─切分：把宽类别拆成互斥子类
   ├─细化：补足同一节点的关键属性
   ├─连边：连接另一个异常或核心反应
   └─验因：检查方向、时间、必要性和因果
→ 提出只含一个新变量的问题
```

每获得 2—3 个连续肯定，进行一次内部压缩：

- 删除重复表述；
- 把事实按时间或因果排序；
- 标出仍缺失的边；
- 选择能解释最多异常的下一问。

## 玩家逻辑图

使用以下抽象图，而不是编写长故事：

```text
汤面异常 A
→ 相关维度 D
→ 已确认约束 C
→ 核心隐藏条件 H
→ 机制或关系 M
→ 时间与因果 K
→ 最终反应 R
```

节点记录事实，边只允许使用：

- 身份或状态；
- 关系；
- 时间先后；
- 空间包含或距离；
- 动作与结果；
- 意图；
- 因果；
- 字面与真实含义。

一条高质量问题应补充一个节点或一条边。只增加装饰细节、无法连接任何异常的问题应降级。

## 选择下一问的优先级

给候选问题按以下顺序比较：

1. **范围压缩**：回答后能排除多少类解释；
2. **链条邻接**：是否紧接刚确认的事实；
3. **异常覆盖**：是否可能同时解释多个汤面异常；
4. **因果价值**：是否能连接条件与反应；
5. **假设成本**：问题中包含多少未经确认的前提；
6. **重复成本**：是否只是换一种说法再次确认。

优先选择压缩大、邻接强、覆盖多、前提少的问题。

## 否定、部分成立与无关回答的使用

- `不是`：保留其补集约束；如果原问题是合理二分，转向另一半；如果只是随意猜测，返回上一个已确认节点。
- `是也不是`：不要把整句记为真或假。按身份、位置、时间、因果、范围、字面含义和观察视角拆成最小子句，保留已由前文支持的部分，再分别验证其余部分。
- `不相关`：停止该支线；它表示问题不参与必要条件、核心机制、因果链或异常解释，不应解读为“方向接近但细节不全”。
- 连续多次否定：降低具体化程度，回到最近一次肯定，重新做高层切分。
- 连续多次无关：回到身份或状态、时间、动作、关系和动机等基础维度。

## 浓汤推理链

浓汤优先建立：

```text
普通框架
→ 异常是否真实或按字面发生
→ 关键身份、状态或关系
→ 威胁与角色的个人关联
→ 动作机制和时间方向
→ 意图或因果
→ 最终反应为何不可避免
→ 回看全部异常是否由同一条件解释
```

肯定回答应逐步提高接近感、主动性、不可逆性或个人关联。若连续几个肯定只增加背景，没有提高因果压力，应主动寻找连接最终反应的桥接问题。

## 荒诞汤推理链

荒诞汤优先建立：

```text
表面表达
→ 哪个词或动作被按普通语境误读
→ 真实身份、场景或表达目的
→ 一个核心语义支点
→ 全部异常在新语境下同时变得普通
```

避免过早走向复杂或黑暗故事。肯定节点达到两个左右后，应优先尝试语境重构，而非继续增加背景。

## 完整假设的提交条件

只有满足以下条件才提交完整假设：

- 至少存在一条连续的肯定链；
- 关键节点之间已有关系、时间或因果边；
- 假设能解释至少两个异常，或解释唯一异常及最终反应；
- 没有依赖多个未确认的新前提；
- 可用一个最小因果链表达。

提交时只陈述最小闭合链。若主持仅确认其中一部分，退回最小命题继续盘问。

## 常见推理失误

- 得到一个宽泛肯定后直接猜完整故事；
- 把同义改写误当成新问题；
- 连续枚举具体对象，不做互斥分类；
- 把相关性肯定写成事实肯定；
- 在一个问题中加入多个未经确认的前提；
- 沿着肯定分支不断补背景，却不连接其他异常；
- 已经形成闭合链后继续猜测无关细节；
- 记住结论却忘记记录关系方向和时间顺序。

## 提问策略

- 单人和盲测模式每轮只问一个命题。
- 优先选择能压缩范围的维度：身份或状态、关系、关键动作是否按字面发生、时间顺序、地点意义、动机、是否发生严重伤害。
- 先确定维度，再提出完整故事猜测。
- 每次肯定后优先提出子问题或桥接问题，不随机换分支。
- 连续多轮无进展时，回到人、时间、动作和动机四项。
- 搜索停滞时主动索要提示。

## 输出要求

- `单人玩家`：只输出一个问题；把握较高时可输出一个简短假设。
- `协作玩家`：输出 1—3 个候选问题及一个简短当前假设，不得过早宣称确定答案。
- `盲测`：游戏过程中每轮一个问题；结束后仅依据公开过程报告路径和质量指标。

## 真盲测记录

记录：

- 问题顺序；
- 每个问题对应的主持回答；
- 每个回答是否缩小合理假设范围；
- 首次触及核心条件的轮次；
- 最长连续无进展轮数；
- 使用的提示；
- 含糊或矛盾的主持判断；
- 仍然同样合理的替代答案。

结束后计算：

- **PGR｜推进回答率** = 能缩小范围的回答数 ÷ 全部回答数；目标 `>=60%`。
- **MDS｜最大停滞长度** = 连续无进展的最长轮数；目标 `<=4`。

只能根据公开体验审查：

- 是否至少有一条清晰推进路线；
- 汤面是否提供足够入口；
- 揭晓是否依赖外部冷门知识；
- 等价表达是否得到一致判断；
- 核心条件是否解释全部异常；
- 找到核心后是否自然结束，还是仍需另一套独立故事。

不得假装知道汤底，也不得把作者侧模拟称为盲测。
