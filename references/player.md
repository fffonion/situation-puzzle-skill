# 玩家角色

仅在助手需要猜题、协作猜题或进行真盲测时加载本文件。玩家不得读取私密题目文件、汤底、`key_facts`、出题审查记录或出题对话。

## 模式与输出

- `单人玩家`：每轮只提出一个问题；达到完整假设提交条件时，改为提交一个简短完整假设。
- `协作玩家`：每轮给出 1—3 个候选问题和一个简短当前假设；触发终局收敛时，候选中必须包含当前最佳完整假设。
- `盲测`：每轮只提出一个问题；结束后仅依据公开过程评价推理路径和题目质量。

对话中已经出现汤面或主持回答时，默认使用 `单人玩家`；用户要求一起猜时，使用 `协作玩家`。

## 信息隔离

真正盲测只能使用：

- 公开汤面；
- 主持人的 `是`、`不是`、`是也不是`、`不相关`；
- 主持明确发布的提示。

不得请求、定位、查看或根据文件名推断私密 JSON。当前上下文若已见过汤底、`key_facts` 或出题审查记录，盲测已经失效；应改用隔离玩家上下文。

## 推理状态

内部只维护以下五类记录：

1. **已确认事实**：主持明确判定为真；
2. **已确认维度**：某类身份、关系、时间、动作或因果重要，但具体内容尚未确定；
3. **有限肯定**：`是也不是`，表示问题中有明确成立的主线部分，同时存在会改变判断的错误限定；
4. **已排除事实**：主持明确否定；
5. **未决假设**：尚未询问，或问题含义仍不单一。

`是` 只确认问题中的精确命题，不自动确认相邻假设。`是也不是` 不能整体记为真；`不相关` 不能理解为“方向接近”。

## 推理流程

### 1. 选择入口

优先检查能大幅压缩范围的维度：

1. 关键动作是否按字面发生；
2. 人物身份、状态或关系；
3. 时间顺序；
4. 地点是否参与机制；
5. 意图、因果与最终反应；
6. 是否发生严重伤害。

每轮只引入一个新变量。宽类别先做互斥切分，避免逐项枚举具体对象。

### 2. 利用肯定

得到 `是` 后执行：

```text
记录被确认的最小命题
→ 判断它是节点、属性还是关系边
→ 选择一种操作
   ├─切分：把宽类别拆成互斥子类
   ├─细化：补足同一节点的必要属性
   ├─连边：连接另一个汤面异常
   └─验因：确认方向、时间、必要性或因果
→ 提出只含一个新变量的问题
```

肯定回答可承担六种功能：

- **入口肯定**：确认某个高层维度值得继续；下一问在该维度内切分。
- **类别肯定**：确认上位类别；下一问区分少量互斥子类。
- **关系肯定**：确认两个节点有关；下一问补方向、时间、强度或因果。
- **机制肯定**：确认动作或状态转换；下一问连接汤面异常或最终反应。
- **有限肯定**：保留已获支持的部分，只改变一个限定继续验证。
- **闭合肯定**：完整假设已获确认；停止扩写背景并结束。

每获得 2—3 个连续肯定，进行一次内部压缩：删除重复表述，按时间或因果排序，标出缺失的必要边，并选择能解释最多异常的下一问。

### 3. 处理其他回答

- `不是`：若原问题构成合理二分，转向补集；若只是具体猜测，回到最近的已确认节点。
- `是也不是`：按身份、位置、时间、动作、因果、范围、字面含义或观察视角拆分；保留已有证据支持的部分，每轮只验证一个关键限定。
- `不相关`：停止该支线；该命题不参与必要条件、核心机制、因果链或异常解释。
- 连续否定：降低具体程度，回到最近一次肯定重新切分。
- 连续无关：回到人物、时间、动作、关系和动机等基础维度。

同一语义区域连续两次得到 `是也不是` 时，停止同义改写。只定位一个仍未确认、且会改变核心链的变量；若不存在这种变量，下一轮提交完整假设。

## 逻辑图与选问标准

用逻辑图组织事实，避免编写不断膨胀的故事：

```text
汤面异常
→ 相关维度
→ 已确认约束
→ 核心隐藏条件
→ 动作机制或关系
→ 时间与因果
→ 最终反应
```

节点记录事实；边限定为身份或状态、关系、时间、空间、动作与结果、意图、因果、字面与真实含义。

比较候选问题时依次考虑：

1. **范围压缩**：能排除多少类解释；
2. **链条邻接**：是否紧接最近确认的事实；
3. **异常覆盖**：能否同时解释多个异常；
4. **因果价值**：能否连接隐藏条件与最终反应；
5. **前提成本**：包含多少未确认前提；
6. **重复成本**：是否只是换一种说法再次确认。

只增加装饰细节、无法补节点或关系边的问题应放弃。

## 题型路径

### 浓汤

```text
普通框架
→ 异常是否真实或按字面发生
→ 关键身份、状态或关系
→ 威胁与角色的个人关联
→ 动作机制和时间方向
→ 意图或因果
→ 最终反应为何成立
→ 同一隐藏条件是否解释全部异常
```

若连续肯定只增加背景，没有提高因果压力，应转向连接最终反应的桥接问题。

### 荒诞汤

```text
表面表达
→ 被普通语境误读的词或动作
→ 真实身份、场景或表达目的
→ 核心语义支点
→ 全部异常在新语境下同时变得普通
```

获得约两个肯定节点后，优先尝试语境重构，避免继续增加复杂背景。

## 完整假设与终局收敛

达到以下条件时提交完整假设：

- 已形成连续的肯定链；
- 关键节点之间已有关系、时间或因果边；
- 能解释至少两个异常，或解释唯一异常及最终反应；
- 不依赖多个未确认的新前提；
- 能用最小因果链表达。

完整假设按以下顺序表达：

```text
隐藏条件或前史
→ 关键动作
→ 被误读的汤面事实
→ 最终反应及原因
```

提交后若只得到有限肯定，定位仍有歧义的关键变量；最多再用两轮验证该变量，然后提交修订后的完整链。允许保留少量不改变机制的未确认措辞，禁止加入会改变身份、时间、动作机制或因果方向的新前提。

轮次预算：

- 核心条件、时间顺序、动作机制、最终反应四项中已有三项得到支持，且假设能解释全部汤面异常时，优先提交完整假设；停止确认姿势、物件形态、可替换动作和观察角度等装饰细节。
- 第 35 轮起，每轮先检查是否已经解释全部异常和最终反应；若已解释，下一问必须提交完整假设。
- 第 45 轮起，禁止开启新支线或重复确认装饰细节；存在可闭合主线时，下一问必须提交当前最佳完整假设。

## 提示策略

搜索停滞、连续多个问题没有缩小范围，或已有事实无法导出高信息问题时，可以主动索要提示。获得提示后将其作为公开约束，优先连接最近的已确认节点；不得把提示扩写成未经确认的完整故事。

## 常见失误

- 宽泛肯定后立即猜测大量背景；
- 把同义改写当成新问题；
- 连续枚举具体对象，不做互斥分类；
- 把已确认维度升级为具体事实；
- 一个问题加入多个未确认前提；
- 沿肯定分支补背景，却不连接其他异常；
- 主线已闭合后继续确认装饰细节；
- 忘记记录关系方向和时间顺序；
- 临近轮数上限仍开启新支线。

## 真盲测记录与评价

记录：

- 问题及主持回答的顺序；
- 每个回答是否缩小合理假设范围；
- 首次触及核心条件的轮次；
- 最长连续无进展轮数；
- 已发布提示；
- 含糊或矛盾的主持判断；
- 仍然同样合理的替代答案。

结束后计算：

- **PGR｜推进回答率** = 能缩小范围的回答数 ÷ 全部回答数；目标 `>=60%`。
- **MDS｜最大停滞长度** = 连续无进展的最长轮数；目标 `<=4`。

质量判断只依据公开体验：是否有清晰推进路线、汤面是否提供入口、揭晓是否依赖冷门知识、等价表达是否获得一致判断、核心条件是否解释全部异常、找到核心后能否自然结束。

不得假装知道汤底，也不得把作者侧模拟称为盲测。
